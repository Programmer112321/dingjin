Pre-Processing Airborne LiDAR Data: A Complete Pipeline

LiDAR
3DEP
Pre-processing

A step-by-step walkthrough of the full LiDAR pre-processing pipeline in R using lidR — from raw LAZ tiles to clean, normalized, metric-ready point clouds — with in-depth comparisons of decimation and noise removal strategies.
Author

Dingjin Chu

Published

February 15, 2026

Airborne LiDAR point clouds are rarely analysis-ready straight out of the box. Raw tiles from 3DEP, NEON AOP, or proprietary acquisitions often carry noise, inconsistent densities across acquisition campaigns, and missing normalizations. This post documents a reproducible, catalog-level pipeline in R using the lidR package — from raw LAS/LAZ ingestion to a clean, height-normalized, decimated cloud ready for metric computation.

Part 1: Full Pre-Processing & Metric Calculation Pipeline

Stage 1 — Input & Catalog Setup

library(lidR)

# Build catalog from all tiles in a directory
ctg <- readLAScatalog("path/to/las_folder/")

# Drop pre-labeled noise at catalog level (LAS classes 7 = low noise, 18 = high noise)
opt_filter(ctg) <- "-drop_class 7 18"

# Set chunk buffer (required for SOR neighborhood at tile edges)
opt_chunk_buffer(ctg) <- 10   # metres

# Inspect point density across tiles
summary(ctg)

Key decisions at this stage:

  • -drop_class 7 18 removes points already flagged as noise by the data provider before any other processing. This is always the first step — it costs nothing and eliminates obvious junk early.
  • Chunk buffer = 10 m ensures that the k-nearest-neighbour search in Stage 4 (SOR) sees points from adjacent tiles at every edge. Without a buffer, border points are compared only to neighbours in their own tile, producing false noise flags.
  • For 3DEP data, use opt_chunk_size(ctg) <- 500 to process in 500 × 500 m chunks if memory is constrained.

Stage 2 — Ground Classification (if missing)

# Check whether ground points (Class 2) already exist
has_ground <- function(las) any(las@data$Classification == LASGROUND)

# If absent, classify with Cloth Simulation Filter
classify_ground_csf <- function(las) {
  if (!has_ground(las)) {
    las <- classify_ground(las, csf(sloop_smooth = TRUE, class_threshold = 0.5,
                                    cloth_resolution = 0.5, time_step = 0.65))
  }
  return(las)
}

ctg_ground <- catalog_apply(ctg, classify_ground_csf)

3DEP tiles almost always arrive pre-classified (Class 2 is present). CSF is a safety fallback for tiles from other providers or older acquisitions where ground classification is absent or unreliable. CSF works by simulating a cloth dropped onto an inverted point cloud — points that remain within a threshold distance of the settled cloth are labelled as ground.

Stage 3 — Height Normalization

normalize_and_save <- function(las) {
  # Build DTM from ground points
  dtm <- rasterize_terrain(las, res = 1, algorithm = knnidw(k = 10, p = 2))

  # Normalize: Z → height above ground, save as separate attribute
  las <- normalize_height(las, dtm)
  las <- add_lasattribute(las, las@data$Z, "Height", "Height above ground (m)")

  # Restore raw Z (keeps both raw elevation and Height as independent attributes)
  las <- unnormalize_height(las)

  # Filter normalization artifacts and extreme outliers
  las <- filter_poi(las, Height > -0.5 & Height < 80)

  return(las)
}

Saving Height as a separate LAS attribute before calling unnormalize_height() is essential. After unnormalization, Z reverts to raw elevation (metres above sea level), but Height persists as a named attribute — both are now accessible for any subsequent metric computation without re-running the DTM step.

The height filter removes two categories of artifacts:

Filter Removes
Height > -0.5 Sub-ground points from DTM interpolation errors
Height < 80 m High-altitude noise, birds, low-flying aircraft

Stage 4 — Statistical Outlier Removal (SOR)

remove_noise_sor <- function(las) {
  las <- classify_noise(las, sor(k = 15, m = 3))
  las <- filter_poi(las, Classification != LASNOISE)
  return(las)
}

SOR must occur after normalization (so height context is correct) and before decimation (so artificial sparsity from thinning does not mislead the neighbourhood statistics). See the full discussion in Section 2 below.

Parameters:

Parameter Value Meaning
k 15 Number of nearest neighbours per point
m 3 Flag points with mean NN distance > μ + 3σ of the cloud

Stage 5 — Voxel Decimation (optional, recommended for 3DEP)

decimate_catalog <- function(las, min_dens = 5) {
  # Convert target density to voxel edge length
  voxel_res <- 1 / sqrt(min_dens)

  # Floor: never thin below 5 pts/m² to prevent over-thinning
  voxel_res <- min(voxel_res, 1 / sqrt(5))

  las <- decimate_points(las, voxel(voxel_res))
  return(las)
}

3DEP tiles may come from different acquisition years and sensors, producing density gradients across a study area. Voxel decimation enforces a spatially uniform minimum point spacing, preventing high-density zones from dominating derived metrics. See the full comparison in Section 1 below.

Section 1 — Decimation Methods in Depth

Decimation (also called thinning or subsampling) reduces point density to a target level. The choice of algorithm matters: different methods preserve different spatial and structural properties of the cloud.

1.1 Random Thinning

las_random <- decimate_points(las, random(density = 10))

Each point is independently retained with probability \(p = d_\text{target} / d_\text{local}\), where \(d\) is local point density. The selection is spatially blind — it does not consider where a point sits relative to its neighbours.

How it works: estimate current density, compute retention probability, sample points using a Bernoulli draw with that probability.

Strengths: - Fastest algorithm; trivially parallelisable - Preserves the statistical distribution of intensity, return number, and other attributes - No spatial discretisation artifacts

Weaknesses: - Does not produce spatial uniformity — dense clusters remain dense, sparse areas are unchanged - Sensitive to the random seed (reproducibility requires set.seed()) - In mixed 3DEP tiles with 2–30 pts/m² variation, random thinning averages out density but does not eliminate gradients

Best use: quick exploratory analysis where spatial uniformity is not required.

1.2 Voxel Thinning

las_voxel <- decimate_points(las, voxel(res = 0.5))  # 0.5 m voxel edge

3D space is divided into cubic voxels of edge length res. One point is retained per occupied voxel — chosen randomly from all points within that voxel.

How it works: assign each point to a voxel by integer-dividing its X/Y/Z coordinates by res, then randomly select one point from each occupied voxel’s group.

Strengths: - Enforces 3D spatial uniformity — no two retained points can be closer than res in all three dimensions - Highly effective at removing density artifacts from scan angle overlap or multiple-pass acquisitions - Consistent point spacing benefits rasterisation, normal estimation, and metric computation

Weaknesses: - The retained point is random within the voxel — fine-scale vertical structure (e.g., sub-voxel canopy layering) may be degraded - At coarse res, subtle canopy gaps smaller than a voxel are lost - Does not target a specific points/m² — the output density depends on the actual 3D distribution of the cloud

Best use: removing density gradients in mixed 3DEP acquisitions; pre-processing for wall-to-wall AGB modelling.

1.3 Homogenize Thinning

las_homo <- decimate_points(las, homogenize(density = 10, res = 5))

2D space is divided into cells of edge res. Within each cell, points are randomly subsampled to reach exactly density pts/m². Cells already below the target are left untouched.

How it works: compute local density in each res × res cell; if above target, randomly discard excess points; if at or below target, keep all.

Strengths: - Explicitly targets a density (pts/m²) rather than a voxel size - 2D spatial uniformity — horizontal density gradients are removed - Preserves full vertical structure within each cell (no 3D voxelisation) - Good balance between random (too little control) and voxel (too much 3D rigidity)

Weaknesses: - Does not address 3D density variation — points can still cluster vertically - Cell size res introduces a 2D discretisation scale that interacts with metric resolution - Slower than random thinning

Best use: normalising point density for plot-level or pixel-level AGB modelling where horizontal uniformity matters more than 3D uniformity.

1.4 Highest / Lowest Point per Cell

las_high <- decimate_points(las, highest(res = 1))   # one point per 1 m² cell: the highest
las_low  <- decimate_points(las, lowest(res = 1))    # the lowest

Retains only the highest (or lowest) point within each 2D cell. Not a general pre-processing step — these are single-purpose filters.

Use cases:

Method Retained points Application
highest Top-of-canopy Approximate CHM without full rasterisation
lowest Near-ground Bare-earth surface approximation

1.5 Comparison Summary

Method Spatial uniformity Vertical structure Targets density? Speed Recommended for
Random None Preserved Approximately ★★★★★ Exploration
Voxel 3D uniform Partially lost No (size-based) ★★★★☆ Multi-campaign 3DEP
Homogenize 2D uniform Preserved Yes (pts/m²) ★★★☆☆ AGB pixel regression
Highest/Lowest 2D uniform No No ★★★★☆ Surface extraction only
Tip

For 3DEP data with mixed acquisition years, voxel thinning is the safest default. For NEON AOP data (single campaign, uniform density), no decimation is usually needed. For plot-level regression, homogenize preserves vertical profile shape better than voxel.

Section 2 — Noise and Outlier Removal Methods

Noise in airborne LiDAR arises from multiple sources: multi-path reflections off water, birds and insects, atmospheric aerosols, electronic noise in the detector, and normalization artifacts near terrain discontinuities. No single removal method catches all types.

2.1 Class-Based Filtering (Always First)

las <- filter_poi(las, Classification != LASNOISE)
# Or at catalog level:
opt_filter(ctg) <- "-drop_class 7 18"

LAS format defines standard noise classes: Class 7 (low noise, below ground) and Class 18 (high noise, above expected maximum). Many data providers pre-label these during production.

Strengths: zero computation cost; removes obvious, pre-identified noise before any processing.

Weaknesses: only removes what the provider already flagged — does not catch noise that slipped through classification.

Always apply this first, regardless of what follows.

2.2 Height-Based Thresholding

las <- filter_poi(las, Height > -0.5 & Height < 80)

After normalization, any point with Height < -0.5 is a sub-ground artifact from DTM interpolation error; any point above 80 m (or the expected maximum canopy height for the region) is likely noise.

Strengths: extremely fast; region-specific thresholds can be tuned (e.g., Height < 60 in temperate forests; Height < 100 in tropical).

Weaknesses: does not detect isolated floating points within the valid range (e.g., a bird at 15 m looks identical to a mid-canopy return).

When to use: always — as a complement to other methods, not a substitute.

2.3 Statistical Outlier Removal (SOR)

las <- classify_noise(las, sor(k = 15, m = 3))
las <- filter_poi(las, Classification != LASNOISE)

For each point \(i\), compute the mean distance to its \(k\) nearest neighbours:

\[\bar{d}_i = \frac{1}{k} \sum_{j \in \mathcal{N}_k(i)} \|p_i - p_j\|\]

Compute the global mean \(\mu\) and standard deviation \(\sigma\) of \(\bar{d}\) across all points. Flag point \(i\) as noise if:

\[\bar{d}_i > \mu + m \cdot \sigma\]

Strengths: - Catches isolated floating points within the valid height range (birds, aerosols) - Adapts automatically to local point density — thresholds are data-driven, not hand-tuned - Standard, reproducible, and native to lidR

Weaknesses: - Computationally expensive (\(O(n \log n)\) for kNN + linear scan) - Requires chunk buffer = 10 m to avoid false positives at tile edges - In sparse areas (edges of flight swath, steep terrain), even legitimate points may have high mean NN distances and get flagged → consider m = 4 or m = 5 in open terrain - Does not use attribute information (intensity, return number) — purely geometric

Parameter guidance:

Setting k m Notes
Conservative (keep more) 15 4–5 Sparse terrain, open canopy
Standard 15 3 Most forest environments
Aggressive (remove more) 8 2 Dense urban, noisy sensor

Must apply after normalization and before decimation (see Stage 4).

2.5 Isolation Forest (ML-Based)

Isolation Forest is an unsupervised anomaly detection algorithm that identifies noise using the principle that outlier points require fewer binary splits to isolate than inlier points. Unlike SOR, it operates on multiple attributes simultaneously — X, Y, Z, Intensity, ReturnNumber, NumberOfReturns — making it sensitive to spectral and return-structure anomalies in addition to geometric ones.

# Requires reticulate + Python sklearn
library(reticulate)
sklearn <- import("sklearn.ensemble")
iforest <- sklearn$IsolationForest(contamination = 0.01, n_estimators = 100L)

features <- las@data[, .(X, Y, Z, Intensity, ReturnNumber, NumberOfReturns)]
labels <- iforest$fit_predict(as.matrix(features))
las <- filter_poi(las, labels == 1)   # 1 = inlier, -1 = outlier

Strengths: - Multi-dimensional — catches noise invisible to SOR (e.g., low-intensity returns at normal heights from water surfaces) - Contamination rate is interpretable (fraction of cloud expected to be noise) - No assumption about distance distributions

Weaknesses: - Requires Python bridge (reticulate) — not a pure R solution - 100× slower than SOR on large tiles - Sensitive to feature scaling; requires normalisation of input attributes - Not tile-edge-safe without explicit overlap handling

Best use: post-processing validation of SOR results; specialized applications where intensity or return-structure noise is the primary concern.

Important

Recommended combination for 3DEP data:

  1. Class filter (-drop_class 7 18) — always first
  2. Height threshold (Height > -0.5 & Height < 80) — after normalization
  3. SOR (k = 15, m = 3, with 10 m buffer) — after normalization, before decimation

This three-step stack removes the vast majority of LiDAR noise in typical forest and urban environments with minimal false positive rate and manageable computation time.
